# 陪伴：独立开发分支

分支：`feature/android-companion`，基线 `unify-app` 的 `5c2beec`。
这是根据公开功能说明独立实现的安卓陪伴模块，没有使用 Lookus 的源码、账号系统、接口或商标素材。
入口「更多 → 陪伴」。`unify-app`、签名配置、包名、已有 v0.23.4 版本号均保留。
这是一份开发代码，**未真机验证、未打出正式签名 APK、未部署到用户服务器**。

## 本分支实现的范围

| 功能 | 实现和限制 |
| --- | --- |
| 设备注册、双向绑定 | 私人服务器注册码；随机 12 位十六进制邀请，十分钟有效；接收方申请、邀请方最终确认；每台设备最多绑定一个对方 |
| 分项共享 | 位置、状态、用量分别开关；默认不共享；常驻通知可暂停；服务器按当前授权过滤读取 |
| 实时位置与距离 | 安卓 GPS / 网络定位，不要求 Google Play 服务；15 秒 / 1 分钟 / 5 分钟采样；服务端通信约 15 秒一次；不是硬实时保证 |
| 地图、历史轨迹 | OpenStreetMap 底图（osmdroid），本机日期选择、本人／对方、最多七天；标注采集时间、精度；超过五分钟的定位间隔不连线 |
| 网络、电量、充电报备 | 状态快照及变化事件；Wi-Fi 名称受系统授权影响，不可用时明确显示未知 |
| 屏幕、解锁、每日用机时长 | 常驻服务接收亮灭屏和解锁广播；每日时长需用户在系统授权用量访问，Android 9+；系统缺失的记录不编造 |
| 通话状态 | 可选 READ_PHONE_STATE，显示响铃／通话／空闲；不读取号码、通讯录、录音，不等于完整通话清单 |
| 地点自动报备 | 用当前坐标设置最多 20 个地点、200 米半径、精度缓冲，进入／离开通知；无法定位时不猜测到达 |
| 出行状态 | 连续速度达到阈值后，标注“可能乘车”或“停留或步行”；**不是准确的上下车识别** |
| 二人空间 | 文字消息、状态时间线，服务器七天保留；轮询接收，不依赖厂商推送 |
| 生活提醒 | 自选整点早安／晚安；白天每两小时饮水提醒；服务暂停或系统冻结时会延后／缺失 |
| 紧急求助 | 向对方发送求助消息，可结合已共享位置查看；提交成功不等于对方已收到，不替代电话或救援服务 |
| 响铃 | 对方主动允许后，最长 20 秒、可停止；使用闹钟音频类型，**不更改音量、不绕过勿扰、不能保证静音下必响** |
| 一键锁屏 | 对方主动开启且经过系统设备管理授权；仅 force-lock 权限，没有擦除数据权限；可在页面撤销 |
| 暂停、清空、解绑、注销 | 本机立即停止采集；联网后同步服务器；解绑清除双方共享数据并撤销共享；账号删除使令牌失效 |
| 离线补传 | App 私有 SQLite 队列，最多 3000 条、六天以内，恢复网络后按批补传；不把旧定位当成刚获取的位置 |

范围未涵盖：语音／视频聊天、照片相册、桌面小组件、厂商推送、iOS，以及无法确认的宣传功能。
不能把本分支描述成 Lookus 所有功能都已完整复刻、或全天后台可靠性已验证。

## 文件与数据

- 安卓代码：`android/app/src/main/kotlin/com/github/kyosee/venera/companion/`。
- 服务端：`server/nagi_companion/`，Python aiohttp + SQLite，独立端口 8091。
- 安卓设置和设备令牌：Android Keystore AES-GCM 加密，存 `noBackupFilesDir/companion.enc`。
- 安卓离线队列及消息缓存：`noBackupFilesDir/companion_queue.db`，应用私有目录，不进入 Android 备份或 `.nagi` 导出。
- 服务器令牌只存 SHA-256 摘要。轨迹和消息在服务器私有 SQLite 中，依赖主机文件权限／磁盘保护；**不是端到端加密**，服务器管理员可读取。
- 实际服务地址仅从界面输入，不提供硬编码地址。注册码不要提交 Git，也不要发到聊天中。
- 地图瓦片由 OpenStreetMap 提供，会产生对该提供方的地图区域请求；底图国内可用性需测试，不适合大量分发或离线批量下载。

## 服务器部署（独立服务）

不需要改已有 `nagi-share`、coturn 或小站程序。先将本分支的 `server/nagi_companion/` 文件复制到服务器上的单独目录。
通过用户自己打开的 SSH 终端操作；不代用密码登录。

1. 确保安装 Python 3.10+ 和 venv（Ubuntu 可执行 `sudo apt-get install python3-venv`）。
2. 在该目录执行 `sudo bash install-local.sh`。脚本备份已有陪伴程序和 unit，生成仅 root 可读的注册码配置，保留已有数据库和注册码。
3. 备份现有 Nginx 配置，把 `nginx-location.conf.example` 中的 `location /companion/` 加进**已有 HTTPS** 的 server 块；`sudo nginx -t && sudo systemctl reload nginx`。
4. 在自己的服务器终端查看 `sudo cat /etc/nagi-companion.env`，把等号后注册码分别填进两台手机。无需发送给开发助手。
5. App 服务地址填你自己的 HTTPS 地址，加 `/companion`；不要加 `/v1`。
6. 日志：`sudo journalctl -u nagi-companion -n 50 --no-pager`。数据库：`/var/lib/nagi-companion/companion.sqlite3`。

以上每条终端命令均为单行，可分别在手机远程终端粘贴。脚本不自动修改 Nginx，也不修改现有共享服务。
生产环境应使用已有可信 TLS 证书；客户端拒绝 HTTP 和跳转，避免设备凭据被重定向到其他站点。

回滚：关闭陪伴服务 `sudo systemctl disable --now nagi-companion`；撤掉单独添加的 Nginx location 后检测并 reload。
已有小站／共享服务不受代码上的直接改动。要清理敏感数据库时请先决定是否需要备份，不自动删除。

## 编译与分支隔离

不要把整个开发分支覆盖到用户现有 `VeneraX-nagi-suite` 工作目录。先另建 F 盘测试源码目录／测试监听器。
保持 `com.nagisaland.mobile` 和原签名不变；本分支暂不增加 versionCode，因为还没有发布。
同包名同签名的测试 APK 安装到手机仍是覆盖安装，**Git 分支隔离不等于手机双开**；优先备用安卓机，并先导出个人配置。
全新安装仍遵循原工程的 `.nagi` 初次配置导入流程。
正式出包时另行提升 `android/nagisaland.properties`，沿用原签名文件，按交接文档打包；不使用临时签名替换正式签名。

## 检查命令

服务端集成测试：进入 `server/nagi_companion`，运行 `python3 -m unittest -v test_app.py`。
完整工程编译仍需原项目 Flutter / Android / NDK 工具链和本地签名配置。
`tools/check_companion_kotlin.py` 提供**仅新增模块的 Kotlin 类型编译**：下载固定版本依赖到指定临时目录，使用 Android API 35 类库编译新增文件及真实 PageKit。
它只为原有 SuitePanels 的五个颜色常量生成编译适配文件，不编译 Flutter、其他 Activity，也不生成 APK；不能替代完整 Gradle 构建。

## 必须完成的两台真机验收

1. 确认入口、返回、原有游戏库／漫画／番剧／一起看没有回归。
2. 未确认绑定前没有对方数据；拒绝权限仍可进入页面，不能误标“正在共享”。
3. 两台手机分别注册，双向确认，双方选择权限后开始；确认通知栏有停止入口。
4. 前台／锁屏 30 分钟／锁屏数小时／省电模式／Wi-Fi 与 5G 切换，对比时间戳、定位漂移、耗电与断网补传。
5. 对方暂停后，另一方刷新时不再得到位置；网络断开时暂停，恢复后核实服务器状态。界面需明确“待同步”。
6. 日期跨零点、跨时区、轨迹断点、位置权限撤回、近似定位、系统定位关闭不崩溃。
7. 屏幕时长与系统报告比较；重启或服务被杀期间缺失的屏幕事件不补造。
8. 地点边界来回移动是否误报；速度推测不得误显示为确定上下车。
9. 默认无法锁屏／响铃；允许后测试、撤销权限后再次测试；旧命令超过两分钟不执行。
10. 连续使用后解绑、重绑其他测试设备，确认旧对方无法读取旧数据；删除设备后旧 token 失效。

当前已知产品限制：没有厂商推送或开机自动重启；对方服务被系统停止后消息不会即时送达，需要重新打开并开始共享。
位置前台服务要求定位权限，即使只选状态共享也需要该服务权限；后续可拆分纯消息客户端以减少这一限制。
