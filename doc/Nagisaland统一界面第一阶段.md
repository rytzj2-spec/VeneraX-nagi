# Nagisaland 统一界面：第一阶段

开发分支：`feature/android-companion`。原稳定分支和版本号不变，尚未发布 APK。

## 本轮变化

- 新增 `packages/kazumi/lib/nagi_section_header.dart`：漫画、番剧共用标题、搜索／溢出菜单、顶部分类标签；触控目标至少 48，标签横向滚动，支持系统字号。
- 安卓漫画：首页／收藏／探索／分类迁移到顶部，原有搜索、随机漫画、任务、设置继续可达；保留原 Navigator、来源、收藏和阅读记录。
- 安卓番剧：推荐／时间表／追番／我的迁移到顶部，搜索、设置在标题区域；保留 RouterOutlet、RouteVisibility、返回和播放路由。
- 内部分区不再各占一条底栏，底部由原生 SuiteNav 负责全应用切换。安卓横屏同样使用顶部分类，避免与原生左侧分区导航重复。
- 共用 NagiTheme 扩展为卡片、输入框、按钮、弹窗和提示条的基础样式；字体继续沿用用户已有设置。
- 非安卓端仍走原导航；统一主题原有开关保持有效。显式自定义样式的页面不一定自动跟随所有主题设置。

## 未在本轮完成

详情页的内容布局、阅读器和播放器工具栏、下载和历史的统一模型、统一搜索聚合、统一设置中心、内部引擎合并。
番剧子页面原有工具栏仍保留；后续逐页消除重复标题和操作，不在本轮盲删。
这是产品界面层统一的起点，不代表漫画和番剧已经全部重写成一套内部架构。

## 检查与验收

首轮仅通过 Dart Tree-sitter 语法检查。随后已通过 GitHub 标签安装 Flutter 3.47.7，依赖解析和所修改文件的 Flutter analyze 通过，新增导航的 4 项 widget tests 通过。
用户随后选择在本地构建，云端完整打包已停止；未生成本轮 APK、未真机验证。最新导航和构建方式见 [统一侧栏与本地构建](统一侧栏与本地构建.md)。

有工具链后：按仓库指定 Flutter 版本执行依赖解析、分析并编译。两台测试机重点检查：

1. 漫画四个标签仍对应原来的内容；进入详情、阅读再返回不丢路由；首页布局编辑仍可用。
2. 番剧四个标签正常，详情／播放／搜索／设置返回保持正确；原有深链接和原生设置手势可用。
3. 各分区底部只有一条全应用分区栏；横屏不再叠两条侧栏；键盘弹出、旋转和分区切换没有布局溢出。
4. 小屏及系统大字号下标签可滚动、菜单可操作；搜索／任务／随机漫画／设置均可到达。
5. 老收藏、历史、下载和账号仍正常；UI 变化没有触发数据迁移或清理。

## 后续实施顺序

先对漫画／番剧首页和详情页逐一建立共用封面、元数据、操作区组件，再统一设置入口和分组。
阅读、播放、来源解析暂时通过现有模块提供，逐步建立明确接口后再考虑共享历史与下载服务。
每一步保存独立提交，并完成旧数据兼容与真机验证；不通过改包名、清空数据来绕过迁移问题。
