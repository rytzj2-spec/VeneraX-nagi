# 上游同步流程（手动挑着合）

Nagisaland 统一版**不接受上游的自动更新**：漫画、番剧、H 的「检查更新」都关了。
上游有值得要的修复时，按下面的流程拉代码、看 diff、只挑需要的部分合进来。

| 分区 | 上游仓库 | 当前基于 | 在本仓库的位置 |
| --- | --- | --- | --- |
| 漫画 | `Kyosee/VeneraX` | v2.3.6（`.nagi-base`） | 仓库根目录（`lib/`、`pubspec.yaml`、`android/app` 里 VeneraX 的部分） |
| 番剧 | `Predidit/Kazumi` | 2.4.2 | `packages/kazumi/`（只有 Dart 的 `lib/` 和 `pubspec.yaml`）；原生部分在 `android/app/.../kazumi/` |
| H | `Mlr111/Han1meViewer`（或 fork `misaka10032w/Han1meViewer`） | @3d9050e | `android/han/`（原 app 模块）、`android/yenaly_libs/` |

**铁律**：只往自己的仓库提交，永远不往上面三个上游仓库推；新工作开新分支，不要 force push `suite` / `main`。

## 0. 准备（只做一次）

```bash
git remote add vx https://github.com/Kyosee/VeneraX.git
git remote add kz https://github.com/Predidit/Kazumi.git
git remote add han https://github.com/Mlr111/Han1meViewer.git
```

`git remote add` 是给本地仓库登记一个「别人的仓库地址」，以后用简称 `vx` / `kz` / `han` 拉取。只是登记，不会推送任何东西。

## 1. 开一个同步分支

```bash
git checkout suite && git pull origin suite
git checkout -b sync-vx-2.3.7      # 名字按要同步的东西起
```

## 2. 拉上游、看改了什么

### 漫画（VeneraX，整个仓库根目录就是它）

```bash
git fetch vx --tags
git log --oneline v2.3.6..v2.3.7                 # 两个版本之间有哪些提交
git diff --stat v2.3.6 v2.3.7                    # 改了哪些文件
git diff v2.3.6 v2.3.7 -- lib/network/           # 看某个目录的具体改动
```

挑着合：

- 想要某个提交：`git cherry-pick <提交号>`，有冲突就手动改，改完 `git add` 再 `git cherry-pick --continue`。
- 想要整个版本：`git merge v2.3.7`，冲突逐个解决。
  特别注意这几处是我们改过的，上游的版本不要直接覆盖：
  - `android/app/src/main/AndroidManifest.xml`、`android/app/build.gradle`（包名、版本号、Nagisaland 主界面、各分区同一任务）
  - `lib/foundation/app.dart` 的 `veneraXVersion`（合完改成新版本号）
  - `lib/main.dart` 的统一主题，`lib/network/` 的加载优化，各处关掉的「检查更新」
- 合完更新 `.nagi-base`（写新的版本标签）和 `pubspec.yaml` 的 `version`。

### 番剧（Kazumi，只在 `packages/kazumi/` 子目录里）

上游是整个仓库，我们只放了它的 `lib/` 和 `pubspec.yaml`，所以不能直接 merge，要「做成补丁再套到子目录」：

```bash
git fetch kz --tags
git diff --stat 2.4.2 2.4.3 -- lib pubspec.yaml               # 先看改了什么
git diff 2.4.2 2.4.3 -- lib pubspec.yaml > /tmp/kz.patch       # 导出补丁
git apply -3 --directory=packages/kazumi /tmp/kz.patch         # 套到 packages/kazumi 下面
```

`--directory=packages/kazumi` 的意思是把补丁里的路径都加上这个前缀；`-3` 表示冲突时像 merge 一样留下冲突标记让你手改，而不是直接失败。
只想要一部分：把不要的文件从补丁里删掉，或者 `git diff ... -- lib/某个文件` 只导出那个文件。

注意保留：`lib/nagi_theme.dart`（统一主题）、`app_widget.dart` 里套主题的那几行、`flutter_inappwebview` 官方 6.1.5 和 `forMainFrameOnly: false`、Bangumi 镜像回退、关掉的更新检查、播放器网络错误不弹窗。
上游改了原生代码（`android/app/src/main/kotlin/...`）的话，对照着手动改 `android/app/.../kazumi/` 里对应的文件。

### H（Han1meViewer，`android/han` = 上游的 `app/` 模块）

```bash
git fetch han
git log --oneline 3d9050e..han/main
git diff 3d9050e han/main -- app/src > /tmp/han.patch
git apply -3 -p2 --directory=android/han /tmp/han.patch                 # app/src/... → android/han/src/...
git diff 3d9050e han/main -- yenaly_libs > /tmp/yl.patch
git apply -3 --directory=android /tmp/yl.patch                          # yenaly_libs/... → android/yenaly_libs/...
```

`-p2` 是去掉补丁路径里的前两段（`a/app/`），再加上 `android/han`。

注意保留：去掉的 Firebase、关掉的检查更新和崩溃接管、`HFileProvider`、`SuiteHook` / `SuiteDebug` / `SuiteCrashLog`、
`Parser.kt` 里 2026 年网页改版的解析（上游如果也修了解析，对比着取更好的那份）、`themes.xml` 的 Nagisaland 配色。
H 解析在云端没法验证（hanime1 封云端 IP），用手机存的 `内部存储/Nagisaland/debug/h-*.html` 对照。

## 3. 编译、测试、合回 suite

```bash
git push -u origin sync-vx-2.3.7
```

推上去后 Actions「Nagisaland suite build」会自动编（`sync-*`、`unify-*` 分支都会自动编）。
编过了把 APK 下载到 Nagisaland-Mobile 的 `ci\`，双击「出正式包.bat」，装到手机上测。没问题再在 GitHub 上开 PR 合进 `suite`。
